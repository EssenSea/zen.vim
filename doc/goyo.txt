Distraction-free writing mode	*goyo* *goyo.vim*
==============================================================================

1. Introduction	*goyo-introduction*

goyo.vim provides a distraction-free writing environment for Vim.  The text
of the current window is centred on the screen, the surrounding space is
filled by automatically sized padding windows, and interface elements such as
the status line, line numbers and the color column are hidden while Goyo is
active.

The plugin is written in Vim9script and is organised as a standard Vim
package.  See |goyo-installation| for how to install it and |goyo-command| for
the commands it provides.

==============================================================================
2. Installation	*goyo-installation*

Use a plugin manager, or install manually by adding this directory to
'runtimepath': >vim

set runtimepath+=/path/to/goyo.vim
<
Vim loads |plugin/goyo.vim| at startup and defines the |:Goyo| command.  To
load the plugin only on demand, install it under 'packpath' and use
|:packadd|: >vim

packadd goyo
<

*goyo-requirements*
Requirements: ~
Vim 9.1.0000 or newer with the |+vim9script| feature.  If the feature is
missing the plugin prints a message and does not load.

The optional |goyo-translation| support requires |+multi_lang| and the
|gettext()| machinery.

==============================================================================
3. Usage						*goyo-command*

							*:Goyo*
:Goyo [dimensions]
		Enter Goyo.  Run |:Goyo| again to leave.
		[dimensions] sets the size of the content area:
			{width}			width in columns
			{width}%		width as a percentage
			{width}x{height}	width and height
			{width}%x{height}%	both as percentages
		A '+' or '-' may follow a width or height to offset the
		content within the available space, e.g. `:Goyo 90-10x50%+2`.

:Goyo [dimensions]
		While Goyo is active, re-apply the given dimensions.
:Goyo!			Leave Goyo unconditionally, ignoring errors.

Examples: >vim

	:Goyo			" use the configured defaults
	:Goyo 80		" 80 columns wide
	:Goyo 80x20	" 80 columns by 20 lines
	:Goyo 50%x70%	" 50% wide, 70% high
	:Goyo 90-10
<

==============================================================================
4. Options						*goyo-options*

						*g:goyo_width*
g:goyo_width		number or string, default 80 ~
			Default width of the content window, as a number of
			columns or a percentage string.

						*g:goyo_height*
g:goyo_height		number or string, default '85%' ~
			Default height of the content window.

						*g:goyo_margin_top*
g:goyo_margin_top	number or string, default 4 ~
			Top margin.  When |g:goyo_margin_top| or
			|g:goyo_margin_bottom| is set, these take precedence
			over |g:goyo_height|.

						*g:goyo_margin_bottom*
g:goyo_margin_bottom	number or string, default 4 ~
			Bottom margin.

						*g:goyo_bg*
g:goyo_bg		string, default 'black' ~
			Fallback background colour used when the background
			colour of the |hl-Normal| group cannot be determined.

						*g:goyo_linenr*
g:goyo_linenr		boolean, default 0 ~
			When 1, keep line numbers visible in the content
			window.  By default they are hidden.

						*g:goyo_decoration_elements*
g:goyo_decoration_elements ~
			list of strings, default ['~'] ~
			Elements used to decorate the padding windows.

						*g:goyo_decoration_density*
g:goyo_decoration_density ~
			number, default 0.0 ~
			Probability, between 0.0 and 1.0, that a cell
			receives a decoration element.

						*g:goyo_callbacks*
g:goyo_callbacks	list, default not set ~
			A list of two |Funcref|s: the first is called after
			entering Goyo, the second after leaving it.

==============================================================================
5. Autocommands	*goyo-autocmd*

*GoyoEnter*
GoyoEnter|User| event fired after entering Goyo.

*GoyoLeave*
GoyoLeave|User| event fired after leaving Goyo.

Example: >vim

autocmd User GoyoEnter call MyEnterGoyo()
autocmd User GoyoLeave call MyLeaveGoyo()
<

==============================================================================
6. Mappings	*goyo-mappings*

The plugin sets no global key mappings by itself.  It provides two <Plug>
mappings that users may bind: >

<Plug>(goyo-off)leave Goyo
<Plug>(goyo-resize)re-apply the current dimensions
<
Example: >vim

nmap <Leader>z <Plug>(goyo-off)
<
While Goyo is active the following local mappings are installed, unless the
key is already mapped; they are removed again on leaving:

<C-w>R <C-w>H <C-w>J <C-w>K <C-w>L <C-w>| <C-w>_disabled
<C-w>=re-apply the current dimensions
<C-w>> <C-w><adjust the width
<C-w>+ <C-w>-adjust the height

==============================================================================
7. Notes	*goyo-notes*

*goyo-confine*
Some commands, such as |:help|, |:tag| and |:copen|, open a window with
`:topleft split` or `:botright split`.  Such a window spans the whole tab and
would destroy the left and right margins.  When Goyo is active, any window
that lies outside the content column is closed and its buffer is re-opened
with an ordinary `:split` from the master window, so that it stays inside the
content column.

The following plugins are temporarily disabled while Goyo is active and
restored afterwards: vim-airline, lightline.vim, vim-powerline,
vim-gitgutter and vim-signify.

==============================================================================
8. Translation	*goyo-translation*

Messages can be translated using |gettext()|.  The package identifier is
"goyo" and the catalogues live under |goyo-installation| as: >

lang/<lang_id>/LC_MESSAGES/goyo.mo
<
The template is `lang/goyo.pot`.  See |package-translation| for how to create
the `.po` and `.mo` files.

==============================================================================
9. Development	*goyo-development*

The source is organised as a Vim package: >
	plugin/goyo.vim		loads the plugin, defines :Goyo
	autoload/goyo.vim	the implementation (Vim9script)
	doc/goyo.txt		this help file
	doc/goyo-internals.txt	implementation notes
	lang/			message catalogues
	test/			test suite
<
See |goyo-internals| for the built-in mechanisms the implementation uses.
Run the test suite with: >

make test
<
Or directly: >sh

sh test/run.sh vim
<
