Distraction-free writing mode	*zen* *zen.vim*
==============================================================================

1. Introduction	*zen-introduction*

zen.vim provides a distraction-free writing environment for Vim.  The text
of the current window is centred on the screen, the surrounding space is
filled by automatically sized padding windows, and interface elements such as
the status line, line numbers and the color column are hidden while Zen is
active.

The plugin is written in Vim9script and is organised as a standard Vim
package.  See |zen-installation| for how to install it and |zen-command| for
the commands it provides.

==============================================================================
2. Installation	*zen-installation*

Use a plugin manager, or install manually by adding this directory to
'runtimepath': >vim

set runtimepath+=/path/to/zen.vim
<
Vim loads |plugin/zen.vim| at startup and defines the |:Zen| command.  To
load the plugin only on demand, install it under 'packpath' and use
|:packadd|: >vim

packadd zen
<

*zen-requirements*
Requirements: ~
Vim 9.1.0000 or newer with the |+vim9script| feature.

The plugin is written in the vim9-mix layout (see |vim9-mix|): the version
check in plugin/zen.vim is legacy Vim script, so on an older Vim it exits
cleanly with a warning instead of failing on the `:vim9script` command.
Set |g:zen_disable_legacy_warning| to suppress that warning.

Features that were added after 9.1.0000, such as the 'winfixbuf' option
(9.1.0147), are probed before use, so the plugin keeps working on the
earliest supported builds.

The optional |zen-translation| support requires |+multi_lang| and the
|gettext()| machinery.

3. Usage						*zen-command*

							*:Zen*
:Zen [dimensions]
		Enter Zen.  Run |:Zen| again to leave.
		[dimensions] sets the size of the content area:
			{width}			width in columns
			{width}%		width as a percentage
			{width}x{height}	width and height
			{width}%x{height}%	both as percentages
		A '+' or '-' may follow a width or height to offset the
		content within the available space, e.g. `:Zen 90-10x50%+2`.

:Zen [dimensions]
		While Zen is active, re-apply the given dimensions.
:Zen!			Leave Zen unconditionally, ignoring errors.

Examples: >vim

	:Zen			" use the configured defaults
	:Zen 80		" 80 columns wide
	:Zen 80x20	" 80 columns by 20 lines
	:Zen 50%x70%	" 50% wide, 70% high
	:Zen 90-10
<

==============================================================================
4. Options						*zen-options*

						*g:zen_width*
g:zen_width		number or string, default 80 ~
			Default width of the content window, as a number of
			columns or a percentage string.

						*g:zen_height*
g:zen_height		number or string, default '85%' ~
			Default height of the content window.

						*g:zen_margin_top*
g:zen_margin_top	number or string, default 4 ~
			Top margin.  When |g:zen_margin_top| or
			|g:zen_margin_bottom| is set, these take precedence
			over |g:zen_height|.

						*g:zen_margin_bottom*
g:zen_margin_bottom	number or string, default 4 ~
			Bottom margin.

						*g:zen_bg*
g:zen_bg		string, default 'black' ~
			Fallback background colour used when the background
			colour of the |hl-Normal| group cannot be determined.

						*g:zen_linenr*
g:zen_linenr		boolean, default 0 ~
			When 1, keep line numbers visible in the content
			window.  By default they are hidden.

						*g:zen_decoration_elements*
g:zen_decoration_elements ~
			list of strings, default ['~'] ~
			Elements used to decorate the padding windows.

						*g:zen_decoration_density*
g:zen_decoration_density ~
			number, default 0.0 ~
			Probability, between 0.0 and 1.0, that a cell
			receives a decoration element.

						*g:zen_disable_legacy_warning*
g:zen_disable_legacy_warning ~
boolean, default 0 ~
When 1, do not print a warning when the plugin is
loaded on a Vim older than 9.1.0000 (the plugin
still does not load, see |zen-requirements|).

*g:zen_callbacks*
g:zen_callbacks	list, default not set ~
			A list of two |Funcref|s: the first is called after
			entering Zen, the second after leaving it.

5. Autocommands	*zen-autocmd*

*ZenEnter*
ZenEnter|User| event fired after entering Zen.

*ZenLeave*
ZenLeave|User| event fired after leaving Zen.

Example: >vim

autocmd User ZenEnter call MyEnterZen()
autocmd User ZenLeave call MyLeaveZen()
<

==============================================================================
6. Mappings	*zen-mappings*

The plugin sets no global key mappings by itself.  It provides <Plug>
mappings that users may bind: >

<Plug>(zen-open)	open a Zen session
<Plug>(zen-close)	close the current session
<Plug>(zen-toggle)	toggle Zen
<Plug>(zen-off)		alias of <Plug>(zen-close)
<
Example: >vim

nmap <Leader>z <Plug>(zen-toggle)
nmap <Leader>Z <Plug>(zen-close)
<
While Zen is active the following local mappings are installed, unless the
key is already mapped; they are removed again on leaving:

<C-w>R <C-w>H <C-w>J <C-w>K <C-w>L <C-w>| <C-w>_disabled
<C-w>=re-apply the current dimensions
<C-w>> <C-w><adjust the width
<C-w>+ <C-w>-adjust the height

7. Notes	*zen-notes*

*zen-confine*
Some commands, such as |:help|, |:tag| and |:copen|, open a window with
`:topleft split` or `:botright split`.  Such a window spans the whole tab and
would destroy the left and right margins.  When Zen is active, any window
that lies outside the content column is closed and its buffer is re-opened
with an ordinary `:split` from the master window, so that it stays inside the
content column.

The following plugins are temporarily disabled while Zen is active and
restored afterwards: vim-airline, lightline.vim, vim-powerline,
vim-gitgutter and vim-signify.

8. Public API						*zen-api*

Other plugins and user scripts can drive Zen through the following
three functions.  They are the only supported entry points; everything
else in autoload/zen.vim is an implementation detail and may change
between releases.

							*zen#Open()*
zen#Open([{dim}])
		Open a Zen session.  When one is already active the dimensions
		are updated instead of rebuilding the window layout.  {dim} is
		an optional dimension expression, see |zen-command|.

							*zen#Close()*
zen#Close()
		Close the current session.  Safe to call when Zen is not
		active.

							*zen#Toggle()*
zen#Toggle([{dim}])
		Open Zen when it is not active, close it when it is.  {dim}
		has the same meaning as for |zen#Open()|.

In Vim9script these are available through the imported namespace or
through their autoload names: >

	import autoload 'zen.vim'
	zen.Toggle()
	zen#Open('80x20')
<
The |:Zen| command and the |zen-mappings| are thin wrappers around
these functions.


Messages can be translated using |gettext()|.  The package identifier is
"zen" and the catalogues live under |zen-installation| as: >

lang/<lang_id>/LC_MESSAGES/zen.mo
<
The template is `lang/zen.pot`.  See |package-translation| for how to create
the `.po` and `.mo` files.

10. Development						*zen-development*

The source is organised as a Vim package: >
	plugin/zen.vim		loads the plugin, defines :Zen
	autoload/zen.vim	the implementation (Vim9script)
	doc/zen.txt		this help file
	doc/zen-internals.txt	implementation notes
	lang/			message catalogues
	test/			test suite
<
See |zen-internals| for the built-in mechanisms the implementation uses.
Run the test suite with: >

make test
<
Or directly: >sh

sh test/run.sh vim
<
